# APEX GP

## Authenticated leaderboard beta

This branch adds an opt-in **Verified Beta Lap** through the Leaderboard menu. Sign in using an email link, choose a public driver name, then drive an outlap and a flying lap on the original map with Balanced setup. Normal races, controls and browser practice records retain their existing behavior. Pausing, losing focus, opening a menu, recovery or leaving all four wheels outside the permitted surface ends a beta attempt. Only the independent server replay can save its lap time.

The beta uses the dedicated APEX GP Free Supabase project in Mumbai. Its Edge Function hosts the portable Fetch API with built-in server credentials. Vercel continues serving the static game. Public configuration contains only the project URL and publishable key; database credentials are never bundled. The Auth SDK loads when the leaderboard needs it. No Realtime subscriptions or database requests run during normal solo racing.

`npm ci && npm run build`, then `npm run dev`. Open the original game on port 4173 or the current review server on port 5188. The callback allowlist contains exact callback URLs for these localhost origins and the existing Vercel domain. Source SQL is in `supabase/schema.sql`, with an applied initial migration and a transactional `supabase/smoke-test.sql` that rolls back all test data. See `docs/database-contract.md`.

The API serves cached top-50 standings and a private personal best, issues database-clock attempt tickets, claims each ticket before replay, and persists accepted results atomically. It enforces ownership, expiration, start budgets, minimum elapsed time, fixed physics/setup/track, ordered gates, duplicate recording hashes and idempotent retries. Equal tick times share a rank. This is a **beta leaderboard with prizes disabled**; bots or fabricated controls that wait out the server clock are not excluded by physics validation alone. Raw replay storage, retention, contest eligibility, human-input review and broader runtime/device validation are still required before prize launch.

Email sign-in currently uses Supabase's default development mail service, which only permits organization-team email addresses. Configure custom SMTP (or a separately configured social provider), suitable Auth rate limits and abuse controls before admitting the Reddit/public beta. Do not disable email confirmation or grant browser roles lap-writing access to bypass setup. Browser roles cannot execute the private leaderboard RPCs; authenticated mutations go through the backend.

## Lap-verification development lab

The first competitive-platform milestone is a separate local prototype. Normal races and practice records are unchanged. Run `npm ci`, then `npm run dev` and open `http://127.0.0.1:4173/verification/`. In a second terminal, run `npm run verifier:dev` to start Cloudflare's local workerd runtime on port 8790; refresh the lab if it was opened first. No cloud login, paid resources or public deployment is required.

Record a reference run (a real input recording generated by an automated driver in the browser), or use the manual diagnostic controls. A full attempt contains an outlap followed by one flying lap. Verify the recording independently on Node or local Workers and compare timing, trajectory end state and ordered gates. The diagnostic diagram is a top-down view of the same frozen original circuit and physics, not a replacement for the game's 3D world.

The production Worker adapter at `workers/verification.mjs` is disabled by default and requires explicit enablement plus a secret token. The separate `verification-local.mjs` entry is loopback-only for tests and must not be publicly deployed. The normal Vercel build does not mount the local lab or verifier endpoints.

`npm test` checks the frozen ruleset manifest and runs all tests. Physics changes require a new verifier ruleset and `node scripts/check-verification.mjs --update`; regenerate the numeric track explicitly with `node scripts/freeze-verification-track.mjs` only when issuing a new track ruleset. Current scoring has 8.333 ms tick resolution. This lab establishes physics replay feasibility, not authentication, real-time input provenance or prize eligibility. See `artifacts/verification-evidence.md` for evidence and limitations.

The **original 3.753 km map is the default**. Choose **Navi Mumbai city · BETA** in Race Setup (or use `?map=city`) to test the work-in-progress geographic map. The title screen also has a map shortcut. Loading a map starts a fresh session; personal bests stay separate. The original map makes no Mapbox SDK, style or tile requests.

## City Map Beta

A browser-based 3D open-wheel racer using the user's selected Mapbox city area around Jewel Lake, Navi Mumbai. The current street-aligned circuit measures approximately 3.626 km. Cars, asphalt, kerbs, barriers and the mapped mall model share Mapbox's WebGL canvas and camera. Buildings, roads, shorelines and park surroundings come from the supplied live Mapbox style. Warm sunset lighting and the existing arcade HUD and driving controls are retained. Three.js is vendored locally; the static game runs directly from `dist/`.

The selected footprint is saved in `dist/city-area.geojson`: `[73.002858,19.018653,73.021193,19.035861]` (approximately 3.69 km²). The route in `dist/city-circuit.geojson` follows mapped connected streets, replacing the old image coordinate system. Metres remain the physics unit. The new track has its own personal-best key; old 3.753 km lap records are not compared with it.

Mapbox GL JS 3.33.0, style and tiles require an internet connection. The user's public token is intentionally client-side. Mapbox/OpenStreetMap attribution stays visible and clickable. Mapbox geometry supplies the city's initial fidelity; it is not a surveyed or certified racing circuit. The Nexus Seawoods podium and two blue-glass towers use their mapped footprints and heights. Native objects are cleared from the racing corridor and outside the selected area with a scoped clip layer; tile loading remains managed by Mapbox and is not an offline city export.

The original hand-built 3.753 km map is the root-URL default and is also available at `?map=classic` and is also offered if the live city fails to load. The existing title screen, three game modes, AI, 120 Hz vehicle simulation, wall collisions, ERS rules, manual mobile gestures, pause and recovery remain in place.

Run with Node.js:


## Mobile racing

Touchscreens get manual two-thumb controls and the **Mobile Optimized** graphics preset by default. Race in landscape: slide the left pad to steer, hold the lower GAS region to accelerate, and slide the same finger upward into ERS to boost while keeping the throttle open. Move to the separate BRAKE button to slow down; lift off both pedals to coast. Touch braking overrides throttle and boost. There is no auto-acceleration.

Settings includes steering sensitivity, touch control visibility and a 30 FPS battery-saver option. The compact HUD keeps both thumb zones clear. Pause, focus loss, cancelled touches and rotation clear held inputs. Supported phone browsers request fullscreen and landscape locking on Play; other browsers show a rotation prompt. Returning from portrait requires an explicit resume.

On the city map, Mobile Optimized keeps buildings and facades, uses 1024-pixel car/track shadows, disables native 3D trees, and adapts the shared 3D canvas within a 1.4-megapixel budget. High enables 3D trees and 2048-pixel car/track shadows. Performance disables facade detail and shadows. Canvas scaling uses the public Mapbox resize API; a second independently rendered 3D canvas is not layered over the map. The HUD stays independent of the 3D resolution. These settings do not change the 120 Hz vehicle simulation or ERS rules. Physical-device performance varies; responsive browser checks do not certify every phone.

## Vercel Analytics

`npm ci` installs `@vercel/analytics`. `npm run build` copies its browser SDK/license into `dist/vendor/` and writes the separate analytics entry. `vercel.json` runs that build and serves `dist/`. Vercel builds (`VERCEL=1`) enable pageview tracking and use Vercel's supplied observability client configuration when present. Local and Sites builds leave collection disabled.

Enable **Web Analytics** in the Vercel project's Analytics tab, then redeploy. No API key is required in the game. The integration records pageviews; it does not send player names, lap times or custom gameplay events. The current Vercel URL is https://apex-gp-kohl.vercel.app/.

## Driving

- **W / ↑** accelerate; **S / ↓** brake, then reverse.
- **A D / ← →** steer; **Shift** deploy rechargeable ERS.
- **C** cycles the elevated arcade, cockpit, and chase cameras.
- **R** recovers the car to the nearest point on the circuit.
- **Esc / P** pauses. **M** toggles synthesized engine audio.
- **B / MAP** opens the interactive 3D circuit atlas. Drag to orbit, scroll or use + / − to zoom, and toggle landmark/corner labels. The race freezes while the map is open and resumes when it closes.
- **V** toggles a clean, frozen photo view from the grid or during a race.
- **G** opens the garage, **O** opens race setup, and **H** opens help.
- Gamepad: left stick, RT, LT, A for ERS, Y for camera, Start to pause.
- Touch controls appear on devices with coarse pointers.

Grand Prix has eight drivers and three laps. Time Trial records circuit-specific personal bests in browser storage. Free Drive has no finish limit. Race setup offers three difficulty levels, lighting, graphics quality, audio, and an optional driving line. The garage changes the player's livery. The raised gantry fades near the player to keep the elevated camera clear.

Vehicle handling includes speed-dependent steering, lateral tire grip, braking and drag, contact impulses, street-wall collision, slipstreaming, an automatic gearbox, and energy recovery. AI cars use the same vehicle simulation as the player, with braking anticipation and passing lanes. Four sequential checkpoints per lap and a distance jump guard protect lap counting. Runnable tests cover the original handling and full-field Grand Prix checks, mobile gestures, adaptive rendering, car geometry/flickering fixes, and the georeferenced map's bounds, conversion, grid and a complete AI lap without recovery.

## F4 car, garage and driving feedback

The vehicle is an authored **Mygale M21-F4 Generation 2 inspired** model, using the [manufacturer reference](https://www.mygale.fr/wp-content/uploads/sites/2/2021/07/2021.07.22-MYGALE-M21-F4-Press-Release.pdf) and [RPPL series car identification](https://rpplind.com/wp-content/uploads/2025/09/Pre-event_Press-Release_Round-1_Coimbatore.pdf). It is a stylized approximation rather than licensed factory CAD. Wings, narrow nose, sidepod intakes, halo, cockpit, suspension, diffuser and slicks replace the old rainbow vehicle. The existing collision proxy and input bindings are retained.

Garage offers a rotatable 3D preview, front/side/rear views, keyboard orbit, six live liveries and three real handling presets. Balanced preserves the existing handling; High downforce adds 14% lateral grip and 10% aerodynamic drag; Low drag removes 10% from both. Engine power is identical. Presets apply to the next session and lock while a session is in progress. Personal bests are separated by map and setup; Balanced retains the existing browser-storage key.

Acceleration and ERS use camera pullback, a brief deployment impulse, bounded shake, eased FOV, edge streaks and synthesized wind/boost audio. Settings offers Full, Subtle and Off camera effects; OS reduced motion suppresses the new camera motion and moving streaks. Camera effects never affect steering, physics or lap timing. When ERS empties, release and press again to deploy after recharge; holding it cannot repeatedly pulse boost. ERS and the existing performance model remain arcade game mechanics, not a claim of real F4 hybrid equipment or lap performance.

The garage renderer starts lazily and caps its buffer at 700,000 pixels, 1x DPR and 512px shadows. Main-world rendering pauses while the garage is visible. A car uses 27 meshes and approximately 10,070 triangles. Run `npm test` for the geometry, camera bounds, grip/drag, depleted-battery and feedback regressions. Append `?debug=1` for read-only renderer statistics in the canvas `data-render-stats` attribute; no debug overlay appears in normal play.
